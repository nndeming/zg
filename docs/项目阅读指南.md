# 知光平台 项目阅读指南

本文档提供一条由浅入深、按依赖关系组织的代码阅读顺序，帮助新成员快速了解本项目。

## 第一步：建立整体认知（约 10 分钟）

1. **`README.md`** — 项目概述与技术亮点，先对"认证、计数、发布、用户关系、点赞、Feed、搜索、RAG"八大系统建立整体印象。
2. **`pom.xml`** — 通过依赖清单了解技术组件：JWT/OAuth2、Redis/Redisson、Kafka、Caffeine、Elasticsearch、Canal、阿里云 OSS、Spring AI。
3. **`db/schema.sql`** — 数据库表结构是理解业务的最快途径，先看有哪些核心表。
4. **`src/main/resources/application.yml`** — 配置项清单，了解 MySQL、Redis、Kafka、ES、OSS 等外部依赖的连接方式。

## 第二步：按依赖关系读核心代码

代码位于 `src/main/java/com/tongji/` 下，按业务域分包。建议按"认证 → 用户 → 内容 → 计数/关系 → 读侧优化"的顺序阅读：

### 1. `auth/` 认证模块
其他所有接口都依赖它，是最简单的模块，适合热身。

- 重点：`SecurityConfig.java`（路由放行规则）、`JwtService.java`（双令牌）、`AuthController.java`

### 2. `user/` + `profile/` 用户模块
- 领域模型 User、资料 CRUD，代码量小

### 3. `knowpost/` 内容发布模块
核心业务流程：草稿创建 → OSS 直传确认 → 发布。

- 重点：`KnowPostServiceImpl.java`、`KnowPostFeedServiceImpl.java`

### 4. `counter/` 计数系统（点赞/收藏）
本项目最有技术含量的部分之一。

- 重点：`schema/`（Redis SDS 紧凑计数 + 分片位图）、`event/`（Kafka 异步写聚合 + 重建消费）
- 配套阅读：`docs/计数系统设计方案.md`

### 5. `relation/` 用户关系模块
Outbox 模式 + Canal 订阅 binlog + Kafka 异步同步。

- 配套阅读：`docs/用户关系设计方案.md`

### 6. `cache/` + Feed 缓存
三级缓存、hotkey 探测、single-flight，结合 `knowpost/` 中的 Feed 实现一起看。

### 7. `search/` 搜索模块
ES 索引初始化、Canal 消费同步、`function_score` 排序。

### 8. `llm/` AI 模块
RAG 索引与查询、DeepSeek 摘要生成。

## 第三步：查接口与补细节

- **`docs/` 下的 API 接口文档** — 写代码或联调时当字典查，无需通读
- **`common/`、`config/`** — 全局异常处理、线程池、Redisson 等公共组件，遇到时再进去看

## 时间紧？抓重点

如果只想抓住项目亮点，优先阅读：

1. `docs/计数系统设计方案.md`
2. `docs/用户关系设计方案.md`
3. 对应模块的实现代码

这两篇设计文档 + 实现代码是项目中最能体现深度（高并发、最终一致性设计）的部分。
